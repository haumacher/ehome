# What the E-Home model does not hold of an ETS project file (schema 11), as rules of the
# round-trip comparison (test.de.haumacher.ehome.roundtrip.TestRoundTrip, KnxprojDiff):
# importing a sample and exporting it again must reproduce everything not listed here.
# Explained in doc/knx/schema-coverage.md ("Gaps that matter", "Not needed for E-Home") and
# doc/knx/export.md.
#
# Rules (one per line, '#' starts a comment):
#   file <glob>              an archive entry that is not compared
#   skip <path>              an element (with its content) that is not compared
#   skip <path>@<attribute>  an attribute that is not compared ('*' for any attribute)
#   unordered <path>         an element whose children are compared without their order
#   subset <path>            an element of whose children the export writes those the project uses
#   default <path>@<attribute> <values>
#                            the values (separated by commas) meaning the schema default of an
#                            optional attribute; they count as no value (the model reads a missing
#                            boolean as false)
#   text <path>@<attribute>  a translatable text, compared as the text in effect per application
#                            language (de, en): its translation, else the attribute's text
# A path is a suffix of the element path, element names separated by '/', '*' for any element.
# Besides the rules, the comparison ignores whitespace between elements, the order of attributes,
# namespace declarations, empty attribute values (the import reads them as no value), the
# 'Languages' sections (folded into the texts, see 'text') and translations into languages other
# than de and en.

# Project schema 23 (ETS 6): the export writes schema 11 and leaves out what schema 11 has no place
# for (doc/knx/export.md, "Data of newer schemas"): the named values of datapoint subtypes
# (DatapointSubtype/Format), LdCtrlMasterReset, and the definition of TypeColor. The samples are
# schema 11, so no rule below matches these; a schema-23 sample in the round trip would need:
#   skip DatapointSubtype/Format
#   skip LdCtrlMasterReset
#   skip ParameterType/TypeColor
#   skip Options@DownloadInvisibleParameters
#   skip DeviceInstance/ChannelInstances   (haumacher/ehome #122; carried by the .ehome document)
#   skip Rename                            (haumacher/ehome #122)
#   skip ParameterCalculations             (haumacher/ehome #123)
#   skip Static/Script                     (haumacher/ehome #123)
#   skip ParameterValidations              (haumacher/ehome #124)
#   skip ProjectTraces                     (ETS 6's history of the project, not read)
# besides rules for what the import does not read of schema 23 (doc/knx/schema-coverage.md,
# "Project schema 23").

## What E-Home holds that the project file does not

# The datapoint types of the device templates (haumacher/ehome #103, ehome.template): E-Home's own
# repair of an application program, shared by every project, not data of the project. The export
# writes the type of a communication object only where it is entered in the project
# (ehome.physical:Connector#datapointTypes, ComObjectInstanceRef@DatapointType); a type a device
# inherits from its template is not written, so ETS reads the project as before. No rule is needed:
# an imported file carries no template, and test.de.haumacher.ehome.template.TestDeviceTemplates
# checks that a template's type leaves the export unchanged.
